### 2026-07-08 LINE_FOLLOW v8 — 竞赛级加权位置法 + 增益调度 PD

- **背景**: 主人要"国内外最好用的循迹算法"。Nano 调研了 32 篇智能车竞赛技术报告 + Pololu/Arduino 论坛 + GitHub 5 传感器仓库,得出国内外共识最优骨架 = **加权位置法 + 位置式 PD + 5 档增益调度 + 元素识别状态机**。
- **根因诊断**: 之前 5 套算法 (纯 PD / 模糊 PID / 二阶差分预判 / 三档自适应 PD / 查表) 都不稳的根因不在调参,而在**缺了最关键的预处理层** — 5 路灰度本质是 5-bit 离散信号,直接喂 PD 必然抖;查表法又放弃了反馈。
- **改动 1 — 新增 Algorithm/line_tracker.c/h** (5 层管线):
    1. 加权位置法: 5-bit 命中 → 连续 position ∈ [-2, +2]
    2. 3 帧历史投票: 防单帧反光/污点误判
    3. 死区 (|pos|<0.2 → 0) + 一阶低通滤波 (α=0.4)
    4. 5 档增益调度 PD (D1 直道 / D2 小弯 / D3 大弯 / D4 急弯 / D5 丢线) + 0.1 迟滞带防乒乓
    5. 6 状态元素识别状态机 (WAIT_LINE / STRAIGHT / CURVE / CROSS / SHARP / LOST / ERROR)
    6. 丢线三段式处理: 方向记忆 (0~500ms 惯性续行) → 扫掠搜索 (500ms~2s) → 全停 (>3s)
- **改动 2 — Application/config.h** 新增 LINE_FOLLOW v8 段, 所有可调参数集中管理:
    - 5 档 Kp: 8/15/25/40 (经验法则 Kd ≈ 10~20× Kp)

    - 死区 0.2, 滤波 α=0.4, 迟滞 0.1
    - 5 路 sensor 权重 [-2,-1,0,+1,+2]
- **改动 3 — Application/main.c** 加 USE_V8_ADVANCED 开关:

        SPEED_R_BASE = 4 (右轮直行档)
- **标定方法** (主人实测):

### 2026-07-07 升级竞赛级: 模糊 PID 自整定

- **背景**: 主人要"能力最强的", Nano 上国内外竞赛最常用的模糊 PID。
- **核心**: 不再用固定 gain scheduling, 改为根据 err/derr 两个输入 + 25 条模糊规则
  在线连续自整定 Kp, Kd。比 3 档查表更细腻, 直线段自动减 Kd, 弯道自动加 Kp。
- **算法实现**:
    (1) 模糊化: 三角隶属函数, 5 集 (NB/NS/ZE/PS/PB), err 和 derr 各 5 个隶属度
    (2) 规则评估: 5×5 = 25 条规则, AND=min, 输出 Kp/Kd 调整方向
    (3) 解模糊: 重心法 (center of gravity)
- **关键规则设计**:
    ΔKp: err 大时 +PB (强响应); err/derr 同号时 (偏离加速) +PB; 反号时 (回正) 减
    ΔKd: 直线 (ZE,ZE) → NS (减小 Kd, 不放大 sensor 量化噪声 = 治直线摆动!)
         偏离加速 (err/derr 同号) → NB (Kd≈0 不阻止 err 增长 = 大弯顺弯走!)
         回正 (err/derr 反号) → PB (加大 Kd 加速收敛)
- **参数**:
    Kp_base = 1.0, Kd_base = 1.0  (中心值)
    Δkp ∈ [-0.5, +0.5]  (FUZZY_DELTA_GAIN=0.5)
    Δkd ∈ [-0.5, +0.5]
- **保留辅助模块**:
    - position 低通滤波 (LINE_POS_ALPHA=0.5) 平滑量化噪声
    - 轨迹预判 (K_PRED=1.5) 提前减速+加强转向
    - SHARP 直角反转兜底
- **新增宏**:
    FUZZY_KP_BASE     = 1.0
    FUZZY_KD_BASE     = 1.0
    FUZZY_DELTA_GAIN  = 0.5
- **调参旋钮**:
    直线还摆 → FUZZY_KD_BASE 1.0 → 0.8 (整体减小 Kd)
    弯道转不过 → FUZZY_KP_BASE 1.0 → 1.2 (整体加大 Kp)
    Δ 太小没效果 → FUZZY_DELTA_GAIN 0.5 → 0.8

### 2026-07-07 修直线段摆动 (sensor 量化抖动放大)

- **现象**: 主人反馈"直线段摆来摆去" + "回正太强"
- **根因**: 5 路灰度 position 是离散值 (-2/-1/0/1/2), 相邻档跳变 1.0
    直线段车在 M/L2/R1 间晃, derr=±1
    kd=2.4 × derr=1 = ±2.4 加到 turn → 一个周期 duty 差 4.8 档 → 大幅反向打 → 摆动
- **修复 (三层)**:
    (1) position 低通滤波 (α=0.5) — 平滑量化跳变
    (2) 死区 |err|<0.3 不修正 — 直线段小抖动完全忽略
    (3) 大幅降低小 err 档 Kd (2.4 → 0.8) — 不再放大噪声
- **新参数表 (三档自适应 PD)**:
    |err| < 0.3  → 死区 turn=0
    |err| < 0.5  → kp=0.4, kd=0.8   (微调: 柔和)
    |err| < 1.5  → kp=1.0, kd=1.0   (常规弯: 中等)
    |err| >= 1.5 → kp=1.4, kd=0.2   (大弯: Kd≈0 不抑制转向)
- **新增宏**:
    LINE_DEAD_ZONE  = 0.3   (死区阈值)
    LINE_POS_ALPHA  = 0.5   (滤波系数)
- **回答主人疑问**: "回正会不会算进预判里?" — 不会。
    预判三个条件之一是 |d2| > |d1| (变化率递增),
    回正过程 |d2| < |d1| (变化率递减), 天然被排除。

### 2026-07-07 加入轨迹预判 (二阶差分 jerk 检测)

- **背景**: 主人指出之前 SHARP 检测是事后补救, 要的是"预判路线轨迹"。
  即: 在车冲到拐角之前, 通过传感器序列推断线在弯曲, 提前减速+加强转向。
- **核心算法: 二阶差分 (jerk) 检测**
  维护最近 4 帧 position 滑动窗口, 算:
    d1 = p[t-2] - p[t-3]    (旧一阶差分)
    d2 = p[t-1] - p[t-2]    (新一阶差分)
    dd = d2 - d1            (二阶差分, jerk)
  三个条件全满足才算预判命中:
    (1) d1, d2 同号且 |d| > 0.15  → 单调偏移 (非噪声)
    (2) |d2| > |d1|               → 变化率递增 (加速偏移, 不是回正)
    (3) |p[t-1]| > 0.5            → 当前明显偏离中线
- **预判 vs 回正 — 关键区别**:
    回正: -1.5, -0.8, -0.3, 0   d1=+0.7, d2=+0.5 (一阶同号但 |d| 递减)
    急弯: -0.3, -0.8, -1.5, -2  d1=-0.5, d2=-0.7 (一阶+二阶同号)
  → 算法天然过滤回正过程, 只对真正的"线在弯曲"响应
- **预判响应**:
    pred = clamp(dd, ±1.0)                       (jerk 限幅)
    turn = kp×err + kd×derr + K_PRED × pred      (K_PRED=1.5, 提前加强转向)
    base = 4 - 1 = 3                              (预判命中时减速 1 档, 留转向余量)
- **新增参数**:
    TRAJ_WIN_LEN       = 4      (滑动窗口)
    TRAJ_NOISE_FLOOR   = 0.15   (噪声阈值)
    TRAJ_POS_THRESHOLD = 0.5    (position 阈值)
    LINE_K_PRED        = 1.5    (预判项转向增益)
    LINE_PRED_BRAKE    = 1.0    (预判减速档数)
- **日志新增字段 pred**: -100..+100, 0=无预判
- **下一步**: 主人烧录测试, 重点关注日志 pred 字段:
    直线段 pred 应该 = 0 (无预判, 不会被误触发)
    入弯前 pred 应该出现非零值 (提前感知)
    回正过程 pred = 0 (不会被误判)

### 2026-07-07 修 bug: 直线段误判直角大拐弯

- **现象**: 主人反馈"明明连直角都还没到, 走着走着 90° 大拐弯"
- **根因**: 上一版直角检测条件太松
    - 之前用 `bits==0b00001 || bits==0b00011` 触发 SHARP_LEFT
    - 但直线段车稍微偏一下, L1 也会单亮, 被误判成直角
- **修复: 三重过滤防误判**:
    (1) 严格 pattern — 只认 `bits==0b00001`(仅 L1) / `bits==0b10000`(仅 R2)
        L1+L2 / R1+R2 不再触发 (那可能是大弯道, 不是直角)
    (2) 去抖动 — pattern 必须连续 3 次 (300ms) 才确认
        直线段偶发的 L1 单亮持续不到 300ms, 不会误触发
    (3) 历史约束 — 进入 SHARP 时 `s_last_position` 必须在 ±0.5 内
        说明车原本在直线, 突然跳到极端传感器, 才是真直角
- **新增宏**:
    SHARP_CONFIRM_COUNT  = 3      (300ms 去抖动)
    SHARP_LASTPOS_LIMIT  = 0.5    (进入前 last_position 范围)
- **下一步**: 主人烧录再测, 应该不会再误判。如果真直角反而转不过了,
  说明去抖动把直角也错过了, 把 SHARP_CONFIRM_COUNT 从 3 降到 2。

    BASE = 4.0, 自适应表 kp=0.6/1.2/2.0, kd=2.4/1.5/0.8
    SHARP_SPIN_PWM = 5, SHARP_SPIN_DUTY_MS = 500
