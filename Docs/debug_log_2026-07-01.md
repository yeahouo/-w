```
[running] DOE=0x0x0003F000 DOUT=0x0x00035000 DIN=0x0x00000000
[RUN] 2s

```

**日志解读**：

- `DOE=0x0003F000` → bit 12-17 全部置位 → PA12-17 全部使能输出 ✅
- `DOUT=0x00035000` → bit 12,14,16,17 置位 → 正是 `motor_run_forward()` 应该拉高的 4 个引脚 ✅
- `PINCM=0x81` → PC_CONNECTED + GPIO 功能，配置正确写入 ✅
- `DIN=0x0` → 输入读不到，但这是 INENA 位未置的正常现象，**不影响物理引脚驱动**
- PB22 对照测试：LED 能闪，DIN 也是 0 → 证明 DIN 读不到是普遍现象，不是 PA12-17 的问题

- PINCM 物理索引：PA12=PINCM34 / PA13=PINCM35 / PA14=PINCM36 / PA15=PINCM37 / PA16=PINCM38 / PA17=PINCM39
- DOE/DOUT/PINCM 寄存器写入全部正确
- DIN=0 是 INENA 位未置，**不影响物理引脚驱动**
- PB22 LED 能闪 → GPIO 物理输出机制工作正常

## 7. 所有可能性分析（按概率排序）

### P1 最可能（≈ 50%）：板子的 TB6612 实际接线 ≠ 天猛星标准 PA12-17

**理由**：
- 主人说过"和天猛星差不多" ≠ "完全一样"
- 出厂 demo 知道真正的引脚所以能动
- 我们的代码按天猛星标准配，拉高的可能是没接到 TB6612 的空脚
- 全 GPIO 扫描时电机也没动 → 真实引脚可能在 PA/PB 范围内但被某种方式屏蔽（例如 STBY 没拉高），或者扫描时序不满足 TB6612 启动条件

**验证方法**：
- 拍板子丝印 / 走线照片给 Nano 看
- 找板子厂商要原理图
- 问硬件队友这块底板真实接线

### P2 较可能（≈ 25%）：STBY 没接到 3.3V，而是某个 GPIO 控制

**理由**：
- 天猛星标准是 STBY 直接 3.3V 常使能
- 这块板子可能改成了 GPIO 控制，没拉高就永远待机
- 待机状态下，无论 AIN1/AIN2 怎么翻，H 桥都不会响应

**验证方法**：万用表测 TB6612 STBY 脚电压（应为 3.3V）

### P3 可能（≈ 15%）：TB6612 的 VM 没通电

**理由**：
- USB 可能只供了 MCU 的 3.3V，没通到 TB6612 的 VM（电机电源）
- 出厂 demo 当时动可能是误判（电机"嗡嗡响"被误认为转动）
- VM 是电机驱动电源（4.5-13.5V），没电则 H 桥无法驱动电机

**验证方法**：万用表测 TB6612 VM 脚电压（应 ≥ 4.5V）

### P4 较小（≈ 7%）：板子上有跳线 / 使能开关没拨到位

**理由**：
- 教学板常用跳线帽选择电源路径或外设使能
- 主人没主动报告跳线，可能没注意

**验证方法**：肉眼检查板子上所有跳线帽、拨动开关

### P5 较小（≈ 2%）：TB6612 模块损坏或虚焊

**理由**：全新模块概率低，但虚焊有可能

**验证方法**：换一块 TB6612 模块试

### P6 极小（≈ 1%）：MCU 引脚本身损坏

**理由**：PB22 LED 都能闪说明 MCU 输出机制健康

**验证方法**：示波器看 PA12-17 实际波形

## 11. 关键代码片段归档

### 11.1 `main.c` 当前正确的管脚定义（按天猛星标准）

```c
/* TB6612 接线 — 按立创天猛星 MSPM0G3507 官方标准 (PA12~PA17)
   注意: PINCM 索引按 MSPM0 datasheet 物理引脚顺序,不是 PA_N+1
   注意: STBY 直接接 3.3V 常使能,不占 GPIO */
#define PWM_L_PINCM     IOMUX_PINCM39   /* PA17 = PWMA  */
#define DIR_AIN1_PINCM  IOMUX_PINCM36   /* PA14 = AIN1  */
#define DIR_AIN2_PINCM  IOMUX_PINCM37   /* PA15 = AIN2  */
#define PWM_R_PINCM     IOMUX_PINCM38   /* PA16 = PWMB  */
#define DIR_BIN1_PINCM  IOMUX_PINCM34   /* PA12 = BIN1  */
#define DIR_BIN2_PINCM  IOMUX_PINCM35   /* PA13 = BIN2  */

#define PWM_L_PIN       DL_GPIO_PIN_17  /* PA17 = PWMA */
#define DIR_AIN1_PIN    DL_GPIO_PIN_14  /* PA14 = AIN1 */
#define DIR_AIN2_PIN    DL_GPIO_PIN_15  /* PA15 = AIN2 */
#define PWM_R_PIN       DL_GPIO_PIN_16  /* PA16 = PWMB */
#define DIR_BIN1_PIN    DL_GPIO_PIN_12  /* PA12 = BIN1 */
#define DIR_BIN2_PIN    DL_GPIO_PIN_13  /* PA13 = BIN2 */
```

### 11.2 `ti_msp_dl_config.h` SysConfig 电机引脚宏

```c
/* 电机方向 GPIO (TB6612 AIN1/AIN2/BIN1/BIN2) */
#define MOTOR_DIR_PORT          (GPIOA)
#define MOTOR_AIN1_PIN          (DL_GPIO_PIN_14)
#define MOTOR_AIN1_IOMUX        (IOMUX_PINCM36)
#define MOTOR_AIN2_PIN          (DL_GPIO_PIN_15)
#define MOTOR_AIN2_IOMUX        (IOMUX_PINCM37)
#define MOTOR_BIN1_PIN          (DL_GPIO_PIN_12)
#define MOTOR_BIN1_IOMUX        (IOMUX_PINCM34)
#define MOTOR_BIN2_PIN          (DL_GPIO_PIN_13)
#define MOTOR_BIN2_IOMUX        (IOMUX_PINCM35)
#define MOTOR_DIR_PINS  (MOTOR_AIN1_PIN | MOTOR_AIN2_PIN \
                        | MOTOR_BIN1_PIN | MOTOR_BIN2_PIN)

/* 电机 PWM 引脚 (暂做普通 GPIO) */
#define MOTOR_PWM_PORT          (GPIOA)
#define GPIO_PWM_A_PIN          (DL_GPIO_PIN_17)
#define GPIO_PWM_A_IOMUX        (IOMUX_PINCM39)
#define GPIO_PWM_B_PIN          (DL_GPIO_PIN_16)
#define GPIO_PWM_B_IOMUX        (IOMUX_PINCM38)
#define MOTOR_PWM_PINS          (GPIO_PWM_A_PIN | GPIO_PWM_B_PIN)
```

### 11.3 `ti_msp_dl_config.c` 电机 GPIO 初始化

```c
/* 电机方向 GPIO (TB6612 AIN1/AIN2/BIN1/BIN2) */
DL_GPIO_initDigitalOutput(MOTOR_AIN1_IOMUX);
DL_GPIO_initDigitalOutput(MOTOR_AIN2_IOMUX);
DL_GPIO_initDigitalOutput(MOTOR_BIN1_IOMUX);
DL_GPIO_initDigitalOutput(MOTOR_BIN2_IOMUX);
DL_GPIO_clearPins(MOTOR_DIR_PORT, MOTOR_DIR_PINS);
DL_GPIO_enableOutput(MOTOR_DIR_PORT, MOTOR_DIR_PINS);

/* 电机 PWM 引脚 (PWMA=PA17 / PWMB=PA16) — 当前做普通 GPIO */
DL_GPIO_initDigitalOutput(GPIO_PWM_A_IOMUX);
DL_GPIO_initDigitalOutput(GPIO_PWM_B_IOMUX);
DL_GPIO_clearPins(GPIO_PWM_A_PORT, GPIO_PWM_A_PIN | GPIO_PWM_B_PIN);
DL_GPIO_enableOutput(GPIO_PWM_A_PORT, GPIO_PWM_A_PIN | GPIO_PWM_B_PIN);
```

## 12. 经验教训（Nano 反思）

1. **不该凭"等电池就好"瞎猜** — 主人最初说"电池没到"，Nano 顺着这个就下了"电池是阻塞"的结论，不严谨。后来才知道 USB 都能驱动出厂 demo。
2. **应该早点要求照片** — 丝印和走线信息从一开始就该要。
3. **应该早点要求万用表** — 硬件问题没有万用表等于盲调。
4. **DIN=0 那个坑浪费了时间** — 后来才确认是 INENA 位未置导致，不影响物理输出，但当时绕了一大圈。
5. **主人说"差不多"时要追问** — "差不多" ≠ "一样"，这是关键陷阱。立创天猛星官方板和这块 C07A 不是同一块板。
6. **加 UART 日志做远程诊断**是今天最有价值的决定 — 没有日志，连 DOE/DOUT 对不对都看不到。
